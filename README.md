Тестовое задание: упрощённая PDM-система для импорта CAD-подобных документов, хранения объектов и их версий, работы с BOM, расчёта массы и формирования сводной спецификации.

Проект выполнен на .NET 8 с WPF, PostgreSQL, Dapper и xUnit.

---

## Что реализовано

- импорт CAD-документов из `.a3d` и `.m3d`;
- чтение CAD через `ICadDocumentReader`;
- валидация входных документов;
- транзакционный импорт папки;
- отчёт по принятым, отклонённым и предупреждённым файлам;
- объекты `Assembly`, `Part`, `StandardPart`;
- версии и состояния `InWork`, `Approved`, `Cancelled`;
- повторный импорт с обновлением рабочей версии или созданием новой;
- хранение BOM в PostgreSQL;
- загрузка дерева состава одним recursive CTE;
- расчёт массы вложенных сборок;
- сводная спецификация;
- обнаружение циклов;
- обработка отсутствующей массы;
- поиск объектов;
- карточка объекта и история версий;
- утверждение и аннулирование версий;
- WPF UI по MVVM;
- unit и integration tests.

Предметная модель и правила: типы объектов, состояния версий, переходы состояний и проверка обозначений.

### MiniPdm.Application

Прикладная логика: CAD-абстракции, импорт, валидация, повторный импорт, управление версиями, расчёт массы, спецификация и отчёт импорта.

## Быстрый запуск

### Требования

- Windows;
- .NET 8 SDK или новее;
- Docker Desktop;
- Docker Compose.

```powershell
docker compose up -d
```

```powershell
docker compose ps
```

```text
Host: localhost
Port: 5433

Username: minipdm
Password: minipdm_dev
```


Полный сброс локальной БД:

```powershell
docker compose down -v
docker compose up -d
```

```powershell
dotnet build
```

### 3. Запустить тесты

PostgreSQL должен быть запущен.

## Предметная модель

### Assembly

- обозначение обязательно;
- материал отсутствует;
- собственная масса не хранится;
- масса рассчитывается по BOM.

### Part

- обозначение обязательно;
- материал обязателен;
- масса задаётся для единицы изделия;
- отсутствие массы допускается при импорте с предупреждением.

### StandardPart

- обозначение отсутствует;
- уникальность определяется по наименованию;
- материал отсутствует;
- масса обязательна.

### Обозначение

Пример:

```text
РДЦЛ.304112.501
```

Формат: четыре заглавные кириллические буквы, шесть ASCII-цифр и три ASCII-цифры: `АБВГ.301245.001`.

Обозначения уникальны среди `Assembly` и `Part`.

## Версии и состояния

| Internal | UI |
|---|---|
| `InWork` | В работе |
| `Approved` | Утверждено |
| `Cancelled` | Аннулировано |

Разрешённые переходы:

```text
В работе → Утверждено
В работе → Аннулировано
Утверждено → Аннулировано
```

Обратные переходы запрещены.

Текущая версия — последняя версия объекта, не находящаяся в состоянии `Cancelled`.

## Повторный импорт

| Ситуация | Результат |
|---|---|
| Данные не изменились | `Unchanged` |
| Изменилась версия `InWork` | текущая версия обновляется |
| Изменилась версия `Approved` | создаётся новая версия `N + 1` в `InWork` |
| Все старые версии `Cancelled` | создаётся следующая версия |

Утверждённая версия при повторном импорте не изменяется.

## Импорт и валидация

Процесс импорта:

```text
Поиск файлов
    ↓
Чтение CAD-документов
    ↓
Валидация
    ↓
Каскадное отклонение зависимых сборок
    ↓
Транзакционное сохранение
    ↓
Отчёт импорта
```

Ошибка одного файла не останавливает обработку остальных документов.

Проверяются, в частности:

- формат и уникальность обозначений;
- уникальность `StandardPart` по имени;
- правила материала и массы;
- отсутствие BOM у `Part` и `StandardPart`;
- `quantity > 0`;
- существование referenced components;
- дубли компонентов в одном BOM;
- каскадное отклонение сборок;
- соответствие имени файла данным документа.

## База данных

Основные таблицы:

```text
pdm_object
object_version
bom_link
```

`pdm_object` хранит объект и ссылку на текущую версию.

`object_version` хранит номер версии, состояние, материал, массу и дату создания.

`bom_link` хранит:

```text
parent_version_id
child_object_id
quantity
```

BOM привязан к версии родительской сборки и ссылается на дочерний объект. При расчёте используется текущая версия дочернего объекта.

---

## BOM, масса и спецификация

Полное дерево состава загружается из PostgreSQL одним recursive CTE.

Для вложенных компонентов количества перемножаются по пути.

```text
Сборка
└── Узел ×2
    └── Деталь ×3
```

Итоговое количество детали: `2 × 3 = 6`.

Если необходимый компонент не имеет массы, система не возвращает неполную сумму и не подставляет `0`. Пользователь получает диагностическое сообщение, а компонент остаётся в спецификации с пустой массой.

Спецификация содержит плоский список листовых `Part` и `StandardPart`. Если объект встречается в нескольких ветках, количества суммируются с учётом вложенных множителей.

Циклы обнаруживаются и останавливают рекурсивный обход. В UI такой узел отображается с пометкой `[ЦИКЛ]`.

## Проверка `cad-export`

Результат импорта исходного набора:

```text
CAD-файлов:       45
Прочитано:        44
Ошибок чтения:     1

Принято:          38
Отклонено:         7
Предупреждений:    1
```

При импорте в чистую БД:

```text
Создано:          38
Обновлено:         0
Новых версий:      0
Без изменений:     0
```

### Отклонённые документы

| Файл | Причина |
|---|---|
| `Отдушина.m3d` | Некорректный JSON |
| `Втулка распорная.m3d` | Некорректное обозначение — латинская `P` |
| `Кольцо распорное.m3d` | Некорректный формат обозначения |
| `Шайба стопорная.m3d` | Дублирующееся обозначение |
| `Шайба упорная.m3d` | Дублирующееся обозначение |
| `Привод масляного насоса.a3d` | Отсутствует referenced component |
| `Пробка сливная в сборе.a3d` | Количество компонента равно `0` |

Предупреждение: `Прокладка маслоуказателя.m3d` импортируется без массы.

## Ключевые архитектурные решения

- BOM ссылается на дочерний объект, а не на конкретную дочернюю версию.
- Масса `Assembly` не хранится и всегда рассчитывается из актуального BOM.
- `current_version_id` хранится в `pdm_object` для быстрого доступа и упрощения recursive CTE.
- `Approved`-версия неизменяема: изменение создаёт новую `InWork`.
- CAD отделён интерфейсом; JSON является только одной инфраструктурной реализацией.
